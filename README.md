# CollegeCompass

Find, compare and shortlist engineering colleges in India. You can search and filter colleges, open a full profile, put up to three side by side, and enter your entrance-exam rank to see which colleges admitted students close to it.

> **Sample data.** The colleges are fictional. They're generated by a seeded script and stored in PostgreSQL. Cities, states and exam names are real so the app behaves realistically, but no figure describes a real institution and the reviews are generated text. The app says this in the footer, on the reviews section and on the predictor.

## Overview

Picking a college after an entrance exam usually means jumping between cutoff PDFs, placement reports and review sites. CollegeCompass puts that in one place: filter colleges, compare them on the same attributes, and get a rough idea of where your rank fits.

Most of the effort went into the structure rather than the screens. One validation schema is shared by the server and the browser, all database access sits behind a service layer, the URL holds the whole UI state, and there are tests at each level.

## Features

| Page | Route | What it does |
|---|---|---|
| Colleges | `/colleges` | Debounced search, filters (state, ownership, fee range, rating), sorting and numbered pagination, all kept in the URL |
| Profile | `/colleges/[slug]` | Overview, courses, three years of placements, rating breakdown and reviews |
| Compare | `/compare` | Two or three colleges side by side on 12 attributes, with the best value in each row marked |
| Predictor | `/predictor` | Exam + rank + category → colleges grouped as Likely, Borderline or Reach, based on past closing ranks |

The pages link into each other: a search result can be added to a comparison, a comparison column links to the profile, and a prediction can be sent straight to the comparison.

## Tech Stack

- **Framework:** Next.js 16 (App Router), React 19, TypeScript in strict mode
- **Styling:** Tailwind CSS 4
- **Data:** PostgreSQL (Neon) with Prisma 7 and the `pg` driver adapter
- **Client data:** TanStack Query 5
- **Validation:** Zod 4 (`zod/mini`), shared by the API, forms and URL parsing
- **Testing:** Vitest, Testing Library, Playwright, axe-core
- **CI:** GitHub Actions

## Getting Started

You need Node.js 20.19+ and a PostgreSQL database. Neon's free tier works.

```bash
git clone https://github.com/Neilcodeshere/CollegeCompass.git
cd CollegeCompass
npm install              # also runs prisma generate
cp .env.example .env     # then fill in DATABASE_URL and DIRECT_URL
npm run db:migrate       # create the schema
npm run db:seed          # load the sample dataset
npm run dev              # http://localhost:3000
```

The seed clears the tables and inserts everything inside one transaction, so you can run it again safely. The random seed is fixed, so every environment gets the same 125 colleges.

### Other scripts

## Environment Variables

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | yes | Pooled connection used by the app at runtime (Neon's `-pooler` host) |
| `DIRECT_URL` | yes | Direct connection used by the Prisma CLI for migrations and seeding |
| `NEXT_PUBLIC_SITE_URL` | no | Absolute site URL for metadata and the sitemap; detected automatically on Vercel |

## How It Works

**Server first.** Server Components render the first view of every page, so pages work and can be shared before any JavaScript loads. Client components only handle interaction, and TanStack Query takes over from the server's result so nothing is fetched twice. Server pages call the service layer directly rather than fetching their own API.

**The URL is the state.** Filters, sort, page and predictor inputs all live in the URL. Typing a search uses `replaceState` so you don't get one history entry per keystroke; filters and paging use `pushState` so Back undoes one change at a time. A hand-edited URL with a bad parameter just drops that parameter, while the API applies the same schema strictly and returns a 400.

**The predictor** compares each course's closing rank with your rank as a ratio:

```
ratio = closingRank / yourRank

ratio ≥ 1.10          Likely
0.90 ≤ ratio < 1.10   Borderline
0.70 ≤ ratio < 0.90   Reach
```

A ratio works better than a fixed gap, because 500 ranks matters a lot at rank 1,000 and hardly at all at rank 2,00,000. It uses only the last counselling round of the most recent year. I kept the rules fixed on purpose: there's no real admissions data to train a model on, and fixed thresholds are easy to inspect and test.

The full write-up, with the data model, API reference, performance and security notes, and the design trade-offs, is in [docs/design.md](docs/design.md).

## Deploying

The app is set up for Vercel with a Neon database.

1. Create a Neon project and copy both connection strings.
2. Import the repository into Vercel and add `DATABASE_URL` (pooled) and `DIRECT_URL` (direct).
3. Deploy. The build prerenders every college page, so it needs database access.
4. Once, from your machine, point `.env` at the production database and run `npm run db:deploy && npm run db:seed`.

Migrations don't run during the build, so a preview deployment can't change the production database.

## Current Limitations

- The dataset is fictional and small: 125 colleges, 4 exams, engineering only.
- Cutoffs cover 2023–2025 and one seat type. There are no home-state or other quotas, which real counselling depends on.
- The predictor uses only the latest year and doesn't model year-on-year drift.
- Reviews are generated, and there's no way to submit one.
- There are no accounts, so a comparison belongs to one browser.
- Placement figures are per college, not per branch.
- Search matches substrings, so "Bangalore" won't find "Bengaluru".

## Future Improvements

- Branch-level placement data
- PostgreSQL full-text or trigram search for typo tolerance
- Predictions that use all three years of cutoffs and show a range
- Saved shortlists behind lightweight auth
